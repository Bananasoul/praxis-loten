# Strategie i18n — 7 langues

## Configuration

- **Librairie** : next-intl v4.9.1
- **Fichier config** : `src/i18n/routing.ts`
- **localePrefix** : `'always'` (toutes les URLs contiennent le locale)
- **defaultLocale** : `de` (Eupen est germanophone)

## Les 7 langues

| Code | Langue | Pourquoi |
|------|--------|----------|
| `de` | Allemand | Langue principale d'Eupen (defaut) |
| `fr` | Francais | Deuxieme langue de la region |
| `en` | Anglais | Couverture internationale |
| `nl` | Neerlandais | Patients flamands / frontaliers |
| `tr` | Turc | Communaute turque d'Eupen |
| `ar` | Arabe | Communaute arabophone |
| `pl` | Polonais | Communaute polonaise |

→ Decision documentee dans [[ADR-002-7-langues]]

## Deux couches de traduction

### 1. UI (next-intl classique)

Fichiers `messages/*.json` (de.json, fr.json, ...) pour les chaines d'interface : navigation, boutons, labels.

Acces dans le code : `useTranslations('namespace')`.

### 2. Contenu (hardcode)

Le contenu des pages (articles, bios, services) est directement dans les composants TSX sous forme de `Record<LangKey, string>`.

```typescript
type LangKey = "de" | "fr" | "en" | "nl" | "tr" | "ar" | "pl";
```

→ Decision documentee dans [[ADR-003-contenu-hardcode]]

## Fallback

> [!warning] Etat reel
> Il n'y a **pas de fallback** automatique. Si une cle manque dans une langue, le contenu sera `undefined`. Chaque entree doit etre fournie dans les 7 langues.

## Regle editoriale

Tout nouveau contenu (article, service, bio) **doit** etre fourni dans les 7 langues avant publication. Voir [[editorial-rules]] pour les conventions anti-nocebo par langue.

## URLs

```
https://www.praxisloten.be/de/blog/doser-activite-douleur  ← allemand
https://www.praxisloten.be/fr/blog/doser-activite-douleur  ← francais
https://www.praxisloten.be/en/blog/doser-activite-douleur  ← anglais
...
```

Le slug de l'article est le meme dans toutes les langues (convention kebab-case FR).
